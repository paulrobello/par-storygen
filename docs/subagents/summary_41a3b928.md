# par-storygen Codebase Architecture Summary

**Version**: 0.5.0 | **Python**: ≥3.13 | **Entry point**: `storygen` CLI (Typer)

## Overview

par-storygen is an AI-driven TUI (Textual) choose-your-own-adventure story generator. Players create stories via a wizard, then navigate a branching story tree. Each "beat" is generated by an LLM, illustrated by an image model, and summarized for context continuity. The app supports multiple LLM providers (OpenAI, OpenRouter, Ollama) and image providers (OpenAI, Gemini, Z.AI, Ollama), with TTS narration and HTML book export.

---

## Layer Architecture

```
┌─────────────────────────────────────────────────┐
│  CLI (main.py) → TUI App (app.py)              │  Presentation
├─────────────────────────────────────────────────┤
│  Screens (screens/) + Widgets (widgets/)        │  TUI-specific UI
├─────────────────────────────────────────────────┤
│  Pipeline (pipeline.py)                         │  Story generation orchestration
├─────────────────────────────────────────────────┤
│  LLM (llm/) + Images (images/) + TTS (tts/)    │  AI generation layer
├─────────────────────────────────────────────────┤
│  Core Models (core/models.py)                   │  Domain types (Pydantic)
├─────────────────────────────────────────────────┤
│  Storage (storage/) + Config (config.py)        │  Persistence & configuration
└─────────────────────────────────────────────────┘
```

## 1. Core Layer (`core/`)

### `core/models.py` — Shared Domain Types

The **neutral bottom layer** — no imports from storage, llm, or images. All Pydantic models and type aliases used across the codebase.

**Type Aliases**:
- `NodeId = str`, `CharacterId = str`
- `NarrationStyle = Literal["first_person", "third_person", "fourth_wall"]`
- `Pacing = Literal["slow", "moderate", "fast"]`
- `ReaderLevel = Literal["ages_0_5", "ages_6_10", "ages_11_15", "ages_15_plus"]`
- `ImageStatus = Literal["not_planned", "generating", "done", "failed"]`

**Provider Config Models**:
- `TextProviderConfig` — provider (openai/openrouter/ollama), model, base_url, api_key
- `ImageProviderConfig` — provider (openai/gemini/zai/ollama), model, base_url, api_key

**Story Domain Models**:
- `Theme(title, setting, premise, keywords)` — story theme
- `Tone(preset, custom_descriptor)` — 9 preset tones + custom
- `Character(id, name, backstory, personality, physical_description, portrait_path, portrait_prompt, outfits, ...)` — full character
- `CharacterOutfit(id, name, description, portrait_path, portrait_prompt, created_at)` — named outfit variant
- `Relationship(char_a_id, char_b_id, type, strength, context, updated_at_node_id)` — pairwise relationship
- `RelationshipType(StrEnum)` — ally, rival, neutral, romantic, mentor, student, family, stranger
- `Choice(id, text)` — LLM output choice
- `StoredChoice(Choice)` — persisted choice with `child_node_id` cache link
- `StoryBeat(narration, choices, is_major, is_ending, new_characters, relationship_updates)` — LLM output per beat
- `IllustrationPlan(should_illustrate, image_prompt, featured_character_ids, reasoning)` — illustration decision
- `Summary(text)`, `Recap(text)`, `AdaptedBackstory(backstory)` — agent outputs
- `StoryNode(id, parent_id, narration, choices, is_major, is_ending, image_*, summary_to_here, recap_text, tts_audio_path, created_at)` — persisted node

**Helper**: `one_sentence(text)` — extracts first sentence

### `core/presets.py` — Story Presets

- `StoryPreset(BaseModel)` — TOML-loadable preset (name, theme, tone, art_style, reader_level, etc.)
- `load_curated_presets()` — from bundled `storygen/presets/*.toml`
- `load_custom_presets()` — from `$XDG_CONFIG_HOME/storygen/presets/`
- `save_custom_preset()` — write preset as TOML

## 2. Storage Layer (`storage/`)

### `storage/paths.py` — XDG-compliant Filesystem Layout

All path math for save data. No I/O (except `ensure_game_dirs`).

**Key functions**:
- `data_root()`, `games_root()`, `library_root()`, `config_root()`, `presets_dir()`
- `game_dir(game_id)`, `game_save_file(game_id)`
- `character_portrait_path(game_id, character_id, version)` — versioned portraits
- `character_outfit_path(game_id, character_id, outfit_id)` — outfit portraits
- `character_reference_path(game_id, char_id)` — uploaded reference images
- `node_image_path(game_id, node_id)` — scene illustrations
- `tts_audio_path(game_id, node_id, provider, voice, ext)` — TTS cache
- `safe_join(base, relative)` — path traversal guard
- `ensure_game_dirs(game_id)` — creates all subdirs (0o700)

### `storage/app_state.py` — Per-User Application State

JSON file under `$XDG_CONFIG_HOME/storygen/state.json` with 1-second TTL cache.

**Dataclasses** (frozen):
- `ProviderPrefs` — text provider/model/base_url/api_key
- `ImageProviderPrefs` — image provider/model/base_url/api_key/fallback_provider/fallback_model
- `CharacterImageProviderPrefs` — character portrait provider config
- `WizardDefaults` — pre-fill values for new story wizard
- `TTSPrefs` — TTS provider/voice/auto_read settings

**Key functions** (read/write state.json):
- `read_app_state()`, `write_app_state()` — core I/O with TTL cache
- Provider pref readers/writers: `read_provider_prefs()`, `write_provider_prefs()`, etc.
- Feature toggles: `art_enabled()`, `prefetch_enabled()`, `prefetch_images_enabled()`, `image_streaming_enabled()`, `llm_cache_enabled()`, `auto_select_enabled()`, `auto_recap_enabled()`, `resume_recap_enabled()`
- `write_all_settings()` — atomic write of ALL settings in one JSON rewrite
- `remember_last_story()`, `last_story_id()` — resume support

**Constants exposed**:
- `PROVIDER_CHOICES`, `IMAGE_PROVIDER_CHOICES`, `TTS_PROVIDER_CHOICES` — UI-facing (label, id) pairs
- `SUGGESTED_MODELS`, `SUGGESTED_IMAGE_MODELS` — per-provider model lists
- `PROVIDER_SUPPORTS_REFS` — which image providers support reference images (openai, gemini)
- `IMAGE_API_KEY_ENV`, `TTS_API_KEY_ENV` — env var name mappings
- `GRAPHICS_MODE_CHOICES` — terminal rendering protocol options

### `storage/save.py` — GameSave Model + Load/Save

- `GameSave(BaseModel)` — **the** top-level persisted state:
  - `id` (UUID), `version` (int, current=4)
  - `theme`, `tone`, `narration_style`, `art_style`, `target_major_beats`, `reader_level`, `pacing`
  - `text_config`, `image_config`, `character_image_config` — provider configs **pinned per save**
  - `characters: list[Character]`, `relationships: list[Relationship]`
  - `nodes: dict[NodeId, StoryNode]` — the entire story graph
  - `root_node_id`, `current_node_id`, `endings_reached: list[NodeId]`
  - `creation_prompts: StoryCreationPrompts` — user's wizard prompts
  - `total_image_cost_usd`, `text_total_input_tokens`, `text_total_output_tokens`, `text_total_requests`, `text_calls_by_model`
  - `created_at`, `updated_at`

- `save_game(save)` — atomic JSON write (.tmp + os.replace, 0o600)
- `load_game(game_id)` — load + migrate + backfill creation prompts
- `_migrate(data, from_version)` — forward migrations (v1→v4)
- `prune_subtree(save, node_id)` — remove node + descendants, clean up images/audio
- `delete_game(game_id)`, `list_existing_story_titles(limit)`

### `storage/tree.py` — Pure Tree Traversal Functions

All take `(save: GameSave, node_id: str)`:
- `path_from_root(save, node_id)` → `list[StoryNode]`
- `ancestors(save, node_id)` → `list[StoryNode]` (closest first)
- `children(save, node_id)`, `children_index(save)` → parent→children map
- `descendants(save, node_id)` → BFS-ordered list
- `latest_summary(save, node_id)` → walk ancestors for `summary_to_here`
- `segment_since_last_summary(save, node_id)` → `(prev_summary, segment_nodes)` for summary agent

### `storage/library.py` — Cross-Game Character Library

Persists exported characters under `$XDG_DATA_HOME/storygen/library/<library-id>/`.

**Models**:
- `LibrarySource(save_id, save_title, character_id)` — provenance
- `LibraryCharacter(id, name, backstory, personality, physical_description, portrait_prompt, exported_at, exported_from, source, reference_image_path)` — full library entry

**Functions**:
- `save_library_character(char, portrait_bytes, reference_bytes)` — atomic write (portrait → reference → JSON)
- `load_library_character(library_id)`, `list_library_characters()`, `delete_library_character(library_id)`
- `library_portrait_path(library_id)`, `library_reference_path(library_id)` — path math

### `storage/llm_cache.py` — Debug LLM Exchange Cache

Optional per-save JSON sidecars under `<save-dir>/llm/`:
- `dump_llm_exchange(save_id, node_id, agent_name, raw_bytes)` — atomic write
- `read_llm_exchange(save_id, node_id, agent_name)` → bytes | None

## 3. LLM Layer (`llm/`)

### `llm/models.py` — Re-export shim

Re-exports everything from `core.models` for backward compatibility. **No new types**.

### `llm/prompts.py` — System Prompt Builders

All functions return strings for pydantic-ai agent system prompts:
- `theme_system_prompt()` — propose 3 themes
- `character_system_prompt(theme)` — generate 2-3 characters
- `beat_system_prompt(theme, tone, narration_style, target_major_beats, reader_level, pacing)` — the main beat generator prompt (very detailed with style variety, continuation rules, pacing guidance)
- `illustration_system_prompt()` — decide whether/how to illustrate
- `blurb_system_prompt(theme, characters, narration_style)` — back-cover blurb
- `adapt_backstory_system_prompt(theme)` — rewrite backstory for new theme
- `summary_system_prompt()`, `recap_system_prompt()` — story summary/recap

### `llm/agents.py` — pydantic-ai Agent Factories

Each builds a `pydantic_ai.Agent[model, output_type]`:
- `build_theme_agent(model)` → `Agent[None, Theme]`
- `build_character_agent(model, theme)` → `Agent[None, list[Character]]`
- `build_beat_agent(model, theme, tone, narration_style, ...)` → `Agent[None, StoryBeat]`
- `build_illustration_agent(model)` → `Agent[None, IllustrationPlan]`
- `build_blurb_agent(model, theme, characters, narration_style)` → `Agent[None, str]`
- `build_adapt_backstory_agent(model, theme)` → `Agent[None, AdaptedBackstory]`
- `build_summary_agent(model)` → `Agent[None, Summary]`
- `build_recap_agent(model)` → `Agent[None, Recap]`
- `build_catalog_character_agent(model)` → `Agent[None, list[Character]]`

### `llm/provider_factory.py` — Text Model Factory

- `build_text_model(config: TextProviderConfig)` → `OpenAIChatModel` (via pydantic-ai)
- `validate_config(config)` → `(ok, error_message)`
- `resolve_base_url(provider, override)` — default URLs per provider
- `api_key_env_var(provider)` — env var mapping
- `ALLOWED_PROVIDERS: frozenset` — {"openai", "openrouter", "ollama"}

### `llm/usage.py` — Token Usage Tracking

- `UsageTotals` — mutable in-memory tally (input_tokens, output_tokens, requests, calls_by_model)
  - `.record(model, input_tokens, output_tokens)` — accumulate
  - `.apply_to_save(save)` — merge into GameSave persistent counters
- `record_usage_on_save(save, model, usage)` — direct save increment

## 4. Images Layer (`images/`)

### `images/base.py` — ImageProvider Protocol

```python
@runtime_checkable
class ImageProvider(Protocol):
    async def generate_portrait(description, transparent, art_style, on_partial, reference_image) -> bytes
    async def generate_scene(prompt, reference_portraits, art_style, on_partial) -> bytes
```

`ReferencePortrait(NamedTuple)` — `name: str, data: bytes`

### `images/constants.py` — Shared Constants

- `PORTRAIT_SIZE = "1024x1536"`, `PORTRAIT_QUALITY = "low"`
- `SCENE_SIZE = "1024x1024"`, `SCENE_QUALITY = "auto"`
- `OPENAI_PARTIAL_IMAGES = 2` — streaming preview count

### `images/_prompts.py` — Prompt Builders

Shared across all providers:
- `build_portrait_prompt(description, transparent, art_style, model)` — model-aware format (v2 vs classic)
- `build_scene_prompt(prompt, art_style, model, reference_portraits)` — with ref guidance
- `build_cover_prompt(theme_title, theme_description, art_style, model)` — decorative book cover
- `build_scene_ref_guidance(reference_portraits)` — reference image identification text

### `images/pricing.py` — Cost Estimation

Provider-specific cost tables + unified dispatch:
- `openai_image_cost(size, quality, num_input_refs, partial_images)` → USD
- `gemini_image_cost(model, size)`, `zai_image_cost()`, `ollama_image_cost()` → USD
- `image_cost(provider, model, size, quality, ...)` — single dispatch

### `images/openai_provider.py` — OpenAI Provider

- `OpenAIImageProvider` — `gpt-image-2` / `gpt-image-1.5` / `gpt-image-1`
  - Uses `images.generate` for zero-ref, `images.edit` for ref-anchored
  - Streaming partials via `stream=True, partial_images=N`
  - Retry: 3 attempts with exponential backoff
  - Model-specific quirks: v2 has no transparent background flag, no input_fidelity

### `images/gemini_provider.py` — Gemini Provider

- `GeminiImageProvider` — `gemini-3.1-flash-image-preview` default
  - Uses `google-genai` SDK, passes refs as inline Parts
  - No size param (model infers aspect ratio)
  - Transparency is prompt-only
  - Max 14 reference images

### `images/zai_provider.py` — Z.AI Provider

- `ZaiImageProvider` — GLM-image via OpenAI-compatible endpoint
  - Responses return URL, not base64 (fetches with httpx)
  - **No reference image support** — fires `on_ref_loss` callback
  - Fixed 1280x1280 output

### `images/ollama_provider.py` — Ollama Local Provider

- `OllamaImageProvider` — local inference via OpenAI-compat endpoint
  - Returns base64 responses
  - **No reference image support** — same degradation pattern as Z.AI
  - Fixed 1024x1024 output

### `images/routed_provider.py` — Primary + Fallback Router

- `RoutedImageProvider` — tries primary, falls back on terminal failure
  - `on_fallback(label, exc)` callback for transparency
  - If both fail, surfaces primary's exception with fallback chained

### `images/split_provider.py` — Portrait/Scene Split Router

- `SplitImageProvider(character_provider, art_provider)` — routes portraits to character config, scenes to art config

### `images/provider_factory.py` — Image Provider Factory

- `build_image_provider(config, on_ref_loss)` → `ImageProvider`
- `build_routed_image_provider(primary_cfg, fallback_cfg, ...)` → `RoutedImageProvider`
- `validate_image_config(config)`, `resolve_image_base_url(provider)`, `default_fallback_model(provider)`
- `ImageProviderName = Literal["openai", "gemini", "zai", "ollama"]`
- `ALLOWED_IMAGE_PROVIDERS` — frozenset of valid providers

## 5. Pipeline (`pipeline.py`)

The **core story generation orchestration**. Coordinates the 3-stage beat flow.

**Protocols** (dependency injection):
- `BeatAgentLike` — `.run(prompt, on_narration_delta, raw_sink) → StoryBeat`
- `IllustrationAgentLike` — `.run(beat, characters, raw_sink) → IllustrationPlan`
- `SummaryAgentLike` — `.run(prompt, raw_sink) → Summary`
- `ImageProviderLike` — `.generate_portrait(...)`, `.generate_scene(...)`

**PipelineCallbacks** (dataclass):
- `on_narration_delta`, `on_beat_committed`, `on_image_committed`, `on_image_failed`, `on_new_characters`

**BeatPipeline** (main class):
- `advance(save, from_node_id, choice_id, skip_image, suppress_side_effects, callbacks)` → `StoryNode`
  - Checks prefetch cache → parent cache → generates new beat
  - Stage 1: Stream beat (LLM generates narration + choices + characters + relationships)
  - Stage 2: Illustration planning (concurrent with portrait generation)
  - Stage 3: Scene image generation (background task)
  - Summary: On major beats, generates running summary
  - Handles new character portraits, relationship merging, pacing hints
- `start_prefetch(save, from_node_id, with_images)` — spawn background tasks for all pending choices
- `await_prefetched(save, from_node_id, choice_id)` — await in-flight prefetch
- `cancel_all_prefetches()` — clean shutdown
- `retry_scene(save, node_id)` — regenerate scene image from stored prompt
- `edit_scene(save, node_id, new_prompt, current_image_as_ref)` — regenerate with modified prompt

**Key internals**:
- `_build_beat_prompt(save, from_node_id, choice_text)` — composes the user prompt (CAST, RELATIONSHIPS, STORY-SO-FAR, BEATS, CHOICE, pacing hint)
- `_merge_relationships(save, updates, node_id)` — merge relationship deltas
- `_pacing_hint_for_depth(depth, target, pacing)` — encourage story resolution at appropriate depth
- `background_tasks` — module-level set preventing GC of fire-and-forget tasks
- `_PREFETCH_CONCURRENCY = 3` — semaphore limiting concurrent prefetch LLM calls

## 6. TTS (`tts/`)

### `tts/player.py` — TTSPlayer

- `TTSPlayer` — async TTS with play/pause/resume/stop/restart
  - Wraps `par_tts` library (multi-provider TTS)
  - Audio playback via `ffplay` or `afplay` subprocess
  - `TTSState` enum: IDLE, GENERATING, PLAYING, PAUSED
  - Supports persistent caching (write to path, reuse on replay)
  - Voice management: `refresh_voices()`, `voice_options()`
  - `configure(provider, api_key, voice)` — rebuild provider from settings

## 9. TUI Layer

### `main.py` — CLI Entry Point

- Typer app with `--version` and `--resume` flags
- Default action: launch `StoryGenApp`

### `app.py` — StoryGenApp (Textual App)

The top-level orchestrator wiring everything together.

**Adapters** (bridge pydantic-ai agents → pipeline protocols):
- `_BeatAgentAdapter` — wraps `Agent.run()` → `BeatAgentLike` (delivers narration as one delta)
- `_SummaryAdapter` — wraps summary agent
- `_IllustrationAdapter` — wraps illustration agent

**StoryGenApp(App[None])**:
- `__init__`: loads config, builds text model, builds image provider (split: character + art, each routed with fallback), creates TTS player
- `on_mount`: installs all screens (menu, wizard, load, settings, catalog, style_gallery, preset_picker), pushes menu + intro
- `on_text_provider_changed`, `on_image_provider_changed`, `on_tts_prefs_changed` — live provider switching
- `_start_game(save)` — builds per-save agents + pipeline, switches to PlayScreen
  - Each save pins its own text_config and image_config
  - Builds `BeatPipeline` with adapters, sets up usage tracking
  - Backfills blurb and cover art for legacy saves
- `_build_app_image_provider()` → `SplitImageProvider` with routed providers for both art and character halves
- `_handle_ref_loss(provider_label)` — one-per-session toast when non-ref provider drops refs
- `_handle_fallback(label, exc)` — toast when primary image fails
- `_auto_resume()` — `--resume` support

### Requires Minor Adaptation

| Module | Issue | Fix |
|--------|-------|-----|

| `pipeline.py` | `background_tasks` set is module-level | Web API manages its own task lifecycle |

### Key Insight: `pipeline.py` is Almost Web-Ready

The pipeline is designed with **Protocol-based dependency injection**:
- `BeatAgentLike`, `IllustrationAgentLike`, `SummaryAgentLike`, `ImageProviderLike` are all protocols
- `PipelineCallbacks` is a plain dataclass of async callables
- No Textual imports anywhere in pipeline.py

A web API can:
1. Use the same `pipeline.BeatPipeline` with web-specific callbacks
2. Replace `app_state` reads with request-scoped config
3. Use `GameSave` directly for persistence
4. Use all image/LLM providers as-is

### Recommended Web API Architecture

```
FastAPI/Starlette app
├── Reuses: core/, storage/, llm/, images/, pipeline.py, config.py, export/
├── New: web/routers/ — REST endpoints for story operations
├── New: web/schemas/ — Pydantic request/response models (can reuse core/models)
├── New: web/dependencies.py — DI for pipeline, providers, save loading
└── New: web/ws.py — WebSocket handlers for streaming narration
```

The only adapter needed is a web-specific `PipelineCallbacks` that pushes events via WebSocket/SSE instead of updating Textual widgets.
